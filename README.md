Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

Архитектура приложения
Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.
View - слой представления, отвечает за отображение данных на странице.
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

Базовый код
Класс Component
Является базовым классом для всех компонентов интерфейса. Класс является дженериком и принимает в переменной T тип данных, которые могут быть переданы в метод render для отображения.

Конструктор:
constructor(container: HTMLElement) - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:
container: HTMLElement - поле для хранения корневого DOM элемента компонента.

Методы класса:

render(data?: Partial<T>): HTMLElement - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от Component будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова render и записывать данные в необходимые DOM элементы.

setImage(element: HTMLImageElement, src: string, alt?: string): void - утилитарный метод для модификации DOM-элементов <img>

Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:
constructor(baseUrl: string, options: RequestInit = {}) - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:
baseUrl: string - базовый адрес сервера
options: RequestInit - объект с заголовками, которые будут использованы для запросов.

Методы:
get(uri: string): Promise<object> - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер

post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object> - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется POST запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.

handleResponse(response: Response): Promise<object> - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:
_events: Map<string | RegExp, Set<Function>>) - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:
on<T extends object>(event: EventName, callback: (data: T) => void): void - подписка на событие, принимает название события и функцию обработчик.
emit<T extends object>(event: string, data?: T): void - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.
trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

Данные
В приложении используются две основные сущности данных: товар и покупатель. Эти сущности описываются интерфейсами, которые определяют структуру данных, используемых в моделях. Интерфейсы обеспечивают типизацию и помогают в работе с данными, полученными от API или введенными пользователем.

Интерфейс IProduct
Интерфейс IProduct описывает структуру данных для товара в каталоге. Он используется для хранения информации о каждом товаре, которая отображается в интерфейсе (например, в карточках товара) и передается между компонентами приложения.

interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
id: string — уникальный идентификатор товара, используемый для поиска и манипуляций.
description: string — текстовое описание товара, отображаемое в детальном просмотре.
image: string — путь к изображению товара (относительно CDN), используемый для отображения в карточках и превью.
title: string — название товара, отображаемое в заголовках карточек.
category: string — категория товара, используемая для фильтрации или группировки.
price: number | null — цена товара в синапсах; может быть null для бесплатных товаров.
Интерфейс IBuyer
Интерфейс IBuyer описывает структуру данных для покупателя. Он используется при оформлении заказа для хранения контактной информации и способа оплаты, вводимых пользователем в форме.

interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
payment: TPayment — способ оплаты; TPayment — это тип, определяющий допустимые значения (например, 'card' или 'cash', в зависимости от реализации).
email: string — адрес электронной почты покупателя для связи.
phone: string — номер телефона покупателя.
address: string — адрес доставки покупателя.
Модели данных
Модели данных — это классы, отвечающие за хранение, управление и валидацию данных в приложении. Они разделены по зонам ответственности: хранение товаров, управление корзиной и данные покупателя. Эти классы реализуют бизнес-логику работы с данными, обеспечивая их целостность и предоставляя методы для взаимодействия с другими компонентами (например, с API или представлением).

Класс ProductCatalog
Класс ProductCatalog отвечает за хранение и управление каталогом товаров. Его зона ответственности — хранение массива всех доступных товаров, а также управление выбранным товаром для подробного отображения (например, в модальном окне превью). Класс обеспечивает базовые операции CRUD для товаров, полученных от API или из статических данных.

Конструктор:

Не принимает параметров. Инициализирует пустой массив товаров и null для выбранного товара.
Поля:

items: IProduct[] — массив всех товаров в каталоге; хранит объекты типа IProduct, отвечая за список доступных для покупки товаров.
selectedProduct: IProduct | null — ссылка на выбранный товар для подробного отображения; хранит объект типа IProduct или null, если товар не выбран, и отвечает за временное хранение товара, открытого в модальном окне.
Методы:

setItems(items: IProduct[]): void — сохраняет массив товаров, полученный в параметре items, в поле items. Не возвращает значения.
getItems(): IProduct[] — возвращает массив товаров из поля items типа IProduct[].
getProduct(id: string): IProduct | undefined — возвращает товар по его идентификатору id (типа string) из массива items; если товар не найден, возвращает undefined.
setSelectedProduct(product: IProduct): void — сохраняет товар, полученный в параметре product (типа IProduct), в поле selectedProduct. Не возвращает значения.
getSelectedProduct(): IProduct | null — возвращает выбранный товар из поля selectedProduct типа IProduct | null.
Класс Basket
Класс Basket отвечает за хранение и управление товарами, выбранными покупателем для покупки. Его зона ответственности — поддержка списка товаров в корзине, расчет стоимости и количества, а также проверка наличия товаров. Класс обеспечивает операции добавления, удаления и очистки корзины.

Конструктор:

Не принимает параметров. Инициализирует пустой массив товаров в корзине.
Поля:

items: IProduct[] — массив товаров, выбранных для покупки; хранит объекты типа IProduct, отвечая за список товаров в корзине пользователя.
Методы:

getItems(): IProduct[] — возвращает массив товаров из поля items типа IProduct[].
addItem(item: IProduct): void — добавляет товар, полученный в параметре item (типа IProduct), в массив items. Не возвращает значения.
removeItem(item: IProduct): void — удаляет товар, полученный в параметре item (типа IProduct), из массива items. Не возвращает значения.
clear(): void — очищает массив items, удаляя все товары. Не возвращает значения.
getTotal(): number — возвращает общую стоимость всех товаров в корзине (сумма price каждого товара) типа number.
getCount(): number — возвращает количество товаров в корзине (длина массива items) типа number.
hasItem(id: string): boolean — проверяет наличие товара в корзине по его идентификатору id (типа string) и возвращает true, если товар найден, иначе false.
Класс Buyer
Класс Buyer отвечает за хранение и валидацию данных покупателя. Его зона ответственности — управление контактными данными и способом оплаты при оформлении заказа, включая частичное обновление полей и проверку валидности. Класс обеспечивает сохранение данных без перезаписи существующих значений и очистку.

Конструктор:

Не принимает параметров. Инициализирует поля пустыми значениями (пустые строки или null для payment).
Поля:

payment: TPayment | null — способ оплаты; хранит значение типа TPayment или null, отвечая за выбранный метод оплаты (например, 'card' или 'cash').
email: string — адрес электронной почты; хранит строку, отвечая за контактный email покупателя.
phone: string — номер телефона; хранит строку, отвечая за контактный телефон покупателя.
address: string — адрес доставки; хранит строку, отвечая за адрес покупателя.
Методы:

* setPayment(payment: TPayment): void — сохраняет способ оплаты, полученный в параметре payment (типа TPayment), в поле payment. Не возвращает значения.
* setEmail(email: string): void — сохраняет email, полученный в параметре email (типа string), в поле email. Не возвращает значения.
* setPhone(phone: string): void — сохраняет телефон, полученный в параметре phone (типа string), в поле phone. Не возвращает значения.
* setAddress(address: string): void — сохраняет адрес, полученный в параметре address (типа string), в поле address. Не возвращает значения.
* getBuyerData(): IBuyer — возвращает объект с данными покупателя типа IBuyer, содержащий все поля (payment, email, phone, address).
* clear(): void — очищает все поля, устанавливая их в начальные значения (пустые строки или null). Не возвращает значения.
* validate(): Partial<Record<keyof IBuyer, string>> — валидирует данные покупателя. Проверяет, что каждое поле не пустое (для строк — не пустая строка, для payment — не null). Возвращает объект типа Partial<Record<keyof IBuyer, string>>, где ключи соответствуют полям интерфейса IBuyer, а значения — текстам ошибок (например, {payment: 'Не выбран вид оплаты', email: 'Укажите email'}). Если поле валидно, оно отсутствует в объекте. Правила валидации: поле считается валидным, если оно не пустое.
